# 审计维度 A–I 与分级

每个维度都要有结论；没问题写「查过未发现」。

## A. Token 与样式一致性

硬编码颜色 / 字号 / 间距 / 圆角 / 阴影；内联 style；`!important`；Tailwind 任意值；同一语义多种写法。

## B. 组件复用与选型

对照三档和 `exemplar-rpa-console.md`。原生控件 / 自写弹窗替代组件库；同一功能多套自研；公共组件存在但未用；桌面再引入 antd 以外的第二套 UI 库（手机壳里的 `antd-mobile` 按范本不算）。无组件库时修复方向写「按参考控制台的前端栈迁」。

## C. 布局与间距

Layout 是否唯一；页面内边距、卡片间距、表单栅格；响应式断点。

## D. 交互状态完整性

异步页 loading / empty / error；提交防重；表单校验；危险操作二次确认；成功/失败反馈。

## E. 表格与表单

分页 / 筛选 / 重置；数字列右对齐；空值；日期金额格式；必填与 label。

## F. 反馈与文案

message / notification / 确认用法；术语；中英混用；错误是否告诉下一步。

## G. 可访问性

可点击 div 无键盘支持；图片无 alt；图标按钮无 aria-label；对比度；焦点被全局去掉。

## H. 框架适配

弹层挂载与 z-index；表单受控混用；全局覆盖 `.ant-*` / `.el-*`；主题闪烁 / hydration；locale。Figma 交付是 Arco 时，不把「没用 Arco 组件」算进本维。全局改写 `.ant-btn` 导致 `loading`、`disabled`、`danger`、`type` 失效，记 High。其余大面积内部类名覆盖按 `references/figma-handoff.md` 记。修复方向是 token 对齐，覆盖分批删，按钮改回 antd `Button`。

## I. 工程卡口

lint / rules / Token 文件能否拦住上述问题。

## 运行时补充（有页面可点时）

- 同一屏数字能否加总、口径是否写明
- 空状态：「没有数据」vs「当前筛选为空」
- 筛选项是否覆盖列表已出现的值
- 宽表第一屏是否含决策列；颜色状态有无图例
- 正式导航是否露出试验入口

## 分级

- **High**：系统性或用户直接受损
- **Medium**：局部不一致或状态缺失
- **Low**：细节打磨
- **Info**：记录或待产品/架构决策

## 置信度

- **高**：源码可确认，或线上 DOM/样式/未压缩脚本可确认
- **中**：源码推断，视觉需运行确认
- **低**：取决于设计稿或产品意图
