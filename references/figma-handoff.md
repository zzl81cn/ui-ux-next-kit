# Figma 交付：Arco 不要硬套

预防放在实施规则里，不靠事后审计才发现。新项目开工时把 `templates/cursor-rules/figma-handoff.mdc` 复制到目标仓库 `.cursor/rules/figma-handoff.mdc`。它在改界面和样式时生效。修复提示词的「不要做」已包含同一条，避免修 Token 时又加一层内部类名覆盖。

组织内的界面代码是 **antd v6**。Figma 若交付的是 Arco，把它当视觉参考，不要把 Arco 组件生成成页面，也不要为了像素对齐去改写 antd 的交互。

## 已经出过的问题

有项目按 Figma 的 Arco 稿硬套，用全局样式把 antd 的 `Button` 改成稿上的样子。改完之后按钮只剩外观，antd 原有能力没了：`loading`、`disabled`、`danger`、`type`、`htmlType`、图标按钮都不按组件自己的行为走。新项目禁止再这样做。按钮继续用 antd `Button`，高度、圆角、字号进 token，不要重写 `.ant-btn` 的结构、指针和内部节点。

## 怎么交付、怎么写代码

| | 约定 |
| --- | --- |
| 设计交付 | 手绘视觉规格：色、字号、字重、间距、圆角、状态。不是一份要原样落地的组件库 |
| 代码 | antd v6（桌面）+ 本套件已有的公共组件。手机壳仍只用 `antd-mobile` |
| 外观 | 用 `ConfigProvider` 的 token 和 `--ant-*` 对齐规格。能进 token 的不写死色值 |
| 已有覆盖 | 内部类名（`.ant-*`）分批去掉。一批只迁一类（颜色、圆角、控件高度），迁完再看下一屏 |
| 交互 | 保留组件原来的焦点、键盘、展开、校验、确认。规格没写的交互不要另做一套 |

Arco 里的控件名字、图层结构和 antd 对不上时，选语义最近的 antd 组件，把规格里的尺寸写进 token。不要用一层 CSS 把 antd 画成 Arco，也不要再装一套 UI 库来「还原设计稿」。

UI、UX 规范未尽事宜，严格按照 antd 的规范实现。规范已经写了的尺寸、文案、顺序和状态仍以规范为准。

## 审计怎么记

设计稿是 Arco 时，报告的「设计稿」写：交付为 Arco，代码基准是 antd v6 加手绘规格。下面这两条不算缺陷：

- 页面没有使用 Arco 同名组件
- 交互跟 Arco 演示不一致，但跟 antd 该组件的默认行为一致

下面算缺陷：

- 为大面积贴齐 Arco 而覆盖 `.ant-*`，且这些差异本来可以用 token 表达
- 为贴某一帧而换掉组件交互（自写下拉替代 Select、去掉确认、改掉键盘路径）
- 全局改写 `.ant-btn`，使 `loading`、`disabled`、`danger`、`type`、`htmlType` 失效。这是已经发生过的事故，记为 High
